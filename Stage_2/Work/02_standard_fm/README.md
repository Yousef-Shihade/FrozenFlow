# Step 2 — Standard Flow Matching

**A Computer Vision Project — *Flow Matching as a Layer*** · Stage 2
University of Haifa

---

## Purpose

Train the velocity network $v_\theta(z, t)$ with the **standard** flow-matching objective and
measure what the FM layer does to classification accuracy, against the Stage 1 prototype
baseline reproduced in step 1.

$$z_t = (1-t)\,\hat z_i + t\,p_{y_i}, \qquad u_i = p_{y_i} - \hat z_i,
\qquad \mathcal{L}_\mathrm{FM} = \lVert v_\theta(z_t, t) - u_i \rVert_2^2$$

At inference the feature is transported by $T$ Euler steps and classified with Stage 1's
**unchanged** cosine rule — so the only thing that differs from the baseline is the transport.

## What this objective supervises — and the mismatch it carries

Training only ever visits points **on** the ideal straight line between a feature and its
prototype (`plots/standard_fm_concept.png` shows exactly this). Inference, however, feeds the
network states generated by its *own* previous predictions, which drift off that line.
Nothing in this objective teaches the network how to recover from its own error.

That gap is the entire motivation for step 3's rolled-out training, and the reason the two
are compared under an otherwise identical setup.

**Standard FM training does not depend on $T$.** No rollout happens during training, so one
trained model is evaluated at every $T$ — 27 models, 54 accuracy numbers.

---

## Configuration

Fixed here and reused unchanged in step 3, so any difference in results is attributable to
the objective rather than to a better-tuned network.

| | |
| --- | --- |
| Architecture | MLP, 2 × 512 hidden, SiLU, scalar $t$ concatenated to the input |
| Parameters | ~788 K (512-d features) · ~594 K (384-d) |
| Optimiser | AdamW, lr 1e-3, weight decay 1e-4, batch 64 |
| Gradient clipping | norm 1.0 |
| Epochs | 100, **fixed budget — no checkpoint selection** |
| Flow input | L2-normalized features (step 1) |
| Classification | $\arg\max_c \cos(\hat z_T, \mu_c)$ — unchanged from Stage 1 |

**Why clipping is here even though this objective does not need it.** Backpropagating through
a rollout can amplify gradients, and step 3's objective occasionally diverged without
clipping. Applying it to *both* objectives keeps them configuration-identical, so the
comparison still isolates the objective. It is inert here: enabling it moved every cell in
the table below by at most **0.25 pp** (headline +22.26 → +22.25), which is itself the
evidence that standard FM never needed it.

**Why no validation-based checkpointing** (Stage 1's probe used it): the two objectives are on
different scales and measure different things — velocity error vs. endpoint distance — so no
single validation quantity could select fairly between them. A fixed budget held identical
across both keeps the comparison about the objective. Training curves are recorded instead, so
stability is verified directly.

## Three findings

### 1. The FM layer helps most exactly where prototypes were weakest

The gain tracks how badly the baseline was doing: **+22.3 pp** on DINOv2/Aircraft,
**+5.6 pp** on ResNet-18/Aircraft, roughly neutral on DTD.

This connects directly to Stage 1's separability analysis. On fine-grained Aircraft a single
class-mean vector is a poor summary — Stage 1 found 85 of 100 ResNet-18 classes scoring below
chance on their own prototype — but the discriminative signal *is* present in the feature,
just not aligned with the direction the class mean happens to point in. A learned transport
can move features toward the right mean in a way plain averaging cannot.

### 2. On DTD the FM layer actively hurts at low $K$

**−1.63 pp** at $K = 5$ and **−1.56 pp** at $K = 10$; only at full data does it turn slightly
positive (+0.76). This is a real negative result, not noise — it is consistent across all
three seeds (σ ≈ 0.7–1.1, so the gap is roughly 1.5–2σ) and appears at both values of $T$
and at every $K$ below full.

The reading: DTD's 47 texture classes are broad and visually homogeneous, so a handful of
examples already gives a representative class mean — Stage 1 saw the same thing when
prototypes edged out the linear probe at $K = 5$. There is little for a transport to
recover, and with 235 training features a 788 K-parameter velocity field has ample room to
overfit.

### 3. $T$ barely matters — as it should, for this objective

The largest gap between $T = 4$ and $T = 12$ across all 9 cells is **0.82 pp**, and the sign
is inconsistent. Since standard FM never rolls out during training, more Euler steps simply
integrate the same learned field more finely; there is nothing extra to gain.

This is the contrast to set up for step 3, where $T$ *is* part of training and a separate
model is needed for each value.

## Was L2 normalization actually necessary?

Step 1 chose to L2-normalize the features before the flow, and argued for it from geometry:
against unit-norm prototypes, raw features (norms 24–50) make the target
$u_i = p_{y_i} - z_i$ **99.99 % aligned with $-z_i$**, so the prototype carries almost no
signal. That is a strong argument, but it is still an argument. Stage 1's convention is to
*measure* a design decision rather than reason to it, so this section retrains the identical
objective — same seeds, same subsets, same architecture, same epochs, only `normalize=False`
— and reports what it costs.

At $K = \text{full}$, $T = 4$:

| Encoder / dataset | L2-normalized | raw | cost | raw vs. Stage 1 baseline |
| --- | --- | --- | --- | --- |
| ResNet-18 / DTD | 58.88 | 38.56 | **−20.3 pp** | **−20.3** |
| ResNet-18 / Aircraft | 31.53 | 15.78 | **−15.8 pp** | **−9.7** |
| DINOv2 / Aircraft | 56.56 | 37.92 | **−18.6 pp** | +3.7 |

Two things worth saying precisely, because the obvious summary is slightly wrong:

1. **On both ResNet-18 combinations, the flow trained on raw features is worse than no flow
   at all** — it does not merely fail to help, it destroys 9.7–20.3 pp of the baseline.
2. **DINOv2 is the exception.** Raw features there still beat the baseline by 3.7 pp. The
   decision is not "normalize or the method collapses everywhere"; it is that normalization
   is worth 18.6 pp even on the encoder that tolerates raw features best.

The mechanism shows up directly in the loss. With unit-norm inputs the objective settles at
**0.08–0.20**; with raw inputs at **27–111**. That is the same objective on the same data:
$\lVert u_i \rVert \approx \lVert z_i \rVert \approx 24\text{–}50$, so the network is asked to
regress a vector two orders of magnitude larger whose direction is almost entirely $-z_i$. It
learns to shrink features toward the origin, which is exactly what step 1 predicted and what
the accuracy above measures the price of.

Reported by `tables/normalization_ablation.csv` and `plots/normalization_ablation.png`. The
ablation runs through `cvlabfm.flow`'s real training path via the `normalize` flag, not a
notebook-local copy of the loop, so it exercises the same code the headline results use.

## An invariant the key format protects

**k-shot prototypes are seed-dependent; full-data prototypes are not.**

At $K = 5$ each seed samples a different five images per class, so the class means genuinely
differ — ResNet-18/DTD prototypes for seed 0 and seed 1 have a mean cosine similarity of
**0.878** (worst-matching class 0.787). At $K = \text{full}$ there is nothing left to
subsample and the computation is deterministic, so exactly one set exists.

Step 1 encodes this by keying full-data sets `seed=NA` rather than storing three identical
copies under `seed=0/1/2`. The asymmetry is deliberate: a lookup that ignores the seed then
**fails loudly** instead of resolving to a valid-looking key.

That guard matters because the prototype is the *target* of the flow. Training against the
wrong prototype set raises no error and produces no obviously wrong number — it produces
plausible accuracies that are silently invalid:

- the model is transported toward means built from images it never trained on;
- $\Delta\mathrm{Acc}$ is compared against a baseline computed from a different quantity, so
  the headline gains stop meaning what they claim;
- the seed-to-seed error bars are deflated, because all three seeds would share one target
  set — and those error bars are one of this step's core results.

The prototype lookup therefore stays **inside** the seed loop, with the asymmetry noted at
the call site so it is not moved outside during a later refactor.

## Next step

**Step 3 — Rolled-out FM training.** Same network, same configuration, same subsets and
seeds; only the objective changes:

$$\mathcal{L}_\mathrm{roll} = \lVert \hat z_T - p_{y_i} \rVert_2^2$$

with gradients flowing back through the complete $T$-step rollout, removing the
train/inference mismatch described above. Because $T$ is part of training there, a separate
model is needed per $T$ — 54 models rather than 27, and roughly ten times the compute.

The outcome is **not** the obvious one. Removing the train/inference mismatch does not
translate into better classification — step 3 measures where it does and does not, and
explains why.
